# 能力 → 测试集映射

这份文档回答一个问题：**想验证某个能力（或某个优化是否安全），该跑哪一项、看哪个数、通过线在哪。**

---

## 1. 总表

| 测试集 | 测什么能力 | 题数 | 单题输入 | 判据 | 对 KV 工作的敏感点 |
|---|---|---:|---:|---|---|
| **IFEval** | 指令服从 / 输出格式 | 541 | 74 tok | prompt-level strict acc | 格式崩（量化后最先坏的常是这里） |
| **MMLU-Pro** | 学科知识（10 选 1） | 500 | 220 tok | accuracy | 权重精度；**对 KV 改动最不敏感** |
| **LongBench v2** | 长文检索与整合 | 200 | 51k tok | accuracy | KV 量化 / 驱逐 / 位置外推 |
| **RULER 式 NIAH** | 长文检索的**衰减曲线** | 24 | 8k–128k tok | 按长度 × 位置的 accuracy | **唯一能看出"有效窗口缩水"的项** |
| **一致性对照** | 无损性（缓存/传输） | 自选 40 | 同题目 | **逐 token 100% 相同** | 前缀缓存 / radix / PD 搬运 |

前四项是「答得对不对」，最后一项是「两次答得一样不一样」。**两类判据不能互换**——见 §3。

---

## 2. 按改动类型选测试

| 你要验证的改动 | 必跑 | 判据 | 不必跑 |
|---|---|---|---|
| **KV 量化**（FP8/INT8 KV） | RULER + LongBench v2（long 档）+ MMLU-Pro | RULER 长端掉幅 ≤ 基线；MMLU 掉 ≤ 2pp | 一致性（有损改动，本来就不会一致） |
| **KV 驱逐 / 稀疏**（H2O、SnapKV、Quest） | RULER（看 **depth 维度**）+ LongBench v2 | 深度 50% 处不能明显低于 10%/90%；总分掉 ≤ 3pp | IFEval（与长文无关） |
| **前缀缓存 / radix / HiCache** | 一致性（cold-warm） | **100% 逐 token 相同** | 准确率（无损搬运，准确率抓不住） |
| **PD 分离的 KV 传输** | 一致性（endpoints，A=非 PD，B=PD） | **100% 逐 token 相同** | 同上 |
| **权重量化**（FP8/INT4 权重） | 四项全跑 + `compare` 配对 | 各任务 Δpp 与翻转数，McNemar p | 一致性（权重变了必然不同） |
| **调度 / 并行 / batch 改动** | 一致性 + IFEval | 一致性 100%；IFEval 不掉 | RULER（太重，日常不跑） |
| **换 chat template / 加 system prompt** | IFEval + MMLU-Pro | IFEval 会明显变；两项都要重跑基线 | 一致性（模板变了，本来就不同） |

**"不必跑"这一列同样是结论**：在有损改动上做一致性对照，必然 100% 失败，那不是 bug；在无损改动上看准确率，大概率看不出问题——198 题的 SE 就有 3.6pp。

---

## 3. 两条判据的适用边界

| | 准确率（four tasks） | 一致性（consistency） |
|---|---|---|
| 适用 | 数值计算真的变了（权重量化、蒸馏、剪枝） | 数值计算不该变（缓存、搬运、调度） |
| 判据 | 掉幅 vs 基线，配合 `compare` 配对 | 100% 逐 token 相同，**没有容差** |
| 灵敏度 | 单次跑 6–10pp；配对 2–3pp | 任何一题任何一位不同都算失败 |
| 误用后果 | 拿它测缓存 bug → 看出不来，放过事故 | 拿它测权重量化 → 全员失败，白跑 |

一句话：**判断"该不该一致"，先问这次改动有没有改变数值计算。**

---

## 4. 三档组合

| 档 | 内容 | 题量 | 耗时（~550 tok/s 聚合输出） | 用途 |
|---|---|---:|---:|---|
| **冒烟** | `--limit 10` 各取 10 题 + 一致性 n=10 | 40 | < 5 分钟 | 确认链路通、没崩 |
| **日常回归** | MMLU-Pro 全量 + IFEval + 一致性 + RULER | 541+500+24+40 | ~35 分钟 | 每次改动跑 |
| **发版** | 四项全量 + `compare` + `--ruler-repeat 4` | 1265 | ~2 小时 | 出报告 |

日常回归之所以敢跳过 LongBench v2：它独占 99% 的输入（4M token），但长文信号由 RULER 的
24 题（1.4M token）先兜住；只有 RULER 出现长端掉幅时才需要 LongBench 复核。

命令：

```bash
# 冒烟
python pred.py --model X --tasks mmlu_pro,longbench_v2,ruler --limit 10

# 日常回归
python pred.py --model X --tasks mmlu_pro,ruler
python -m capbench ifeval --model X
python -m capbench consistency --model X --mode cold-warm --n 40 --max-tokens 512

# 发版
python pred.py --model X --tasks all
python -m capbench ifeval --model X
python -m capbench consistency --model X --mode cold-warm --n 40
python result.py --model X --detail
python -m capbench compare --model X --baseline-revision base --revision fp8
```

一致性用 `--max-tokens 512` 而不是 16384：判的是**确定性**，不是答得多好，
输出越短越省、越容易比完。

## 5. 读数时必看的三列

| 列 | 作用 | 异常含义 |
|---|---|---|
| `scored` | 有效评分题数（分母） | 远小于 `n` 说明大量超窗/失败 |
| `over` | 超窗跳过数 | 必须与 `maxlen` 一起报 |
| `官方%` | 命中官方输出格式的比例 | < 95% 时，分数测的是"会不会说格式"而不是能力 |

RULER 另看 `[ruler] 长度 × 位置` 表：**只看按长度聚合的那一行，别看单格**（每格 1 题）。

## 6. 统计分辨率（别过度解读）

| 任务 | 有效 n | SE | 单次跑能看出 | 配对（compare）能看出 |
|---|---:|---:|---:|---:|
| IFEval | 541 | 2.1pp | ~6pp | ~2.2pp |
| MMLU-Pro | 500 | 2.2pp | ~6pp | ~2.2pp |
| LongBench v2 | 158 | 3.8pp | ~11pp | ~5pp |
| RULER（每长度档） | 6 | 12pp@90% | 只够看崩塌 | — |

**规则：差 2pp 以内不要当结论；跨任务不要比大小**（题不同、判分不同）。

## 7. 这套评估覆盖不到什么

| 缺口 | 风险 |
|---|---|
| 结构化输出（JSON schema、函数调用） | 量化最容易破坏、又被四项全掩盖 |
| 数学 / 代码生成 | 无执行判定，退化看不出来 |
| Agent 多轮工具调用 | 多步状态维护完全没测 |
| 中文母语 | 四项全英文 |
| 长文里的**跨段推理** | LongBench 有四选一干扰项，能靠排除法蒙 |
| 显存 / 吞吐 | 本仓库不测性能，见 `sglang.bench_serving` |

前两项要优先补；第三、四项取决于你们的实际负载。**对外报"通用能力 X 分"不成立**——
1265 题的分层子集加自建长文题，只支持"同模型不同配置之间可比"。
